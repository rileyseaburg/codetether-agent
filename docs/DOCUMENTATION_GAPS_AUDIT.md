# Documentation Gaps & Inconsistencies Audit

_Generated by documentation review sub-agent. Scope: README.md, AGENTS.md,
CHANGELOG.md, RELEASE_NOTES, `docs/`, `doc/`, inline rustdoc, and root scratch
files. Each finding lists the source of truth used to verify it._

## Severity Legend
- **P0** — Security / correctness risk, or instruction that fails outright.
- **P1** — Inaccurate content that misleads users or contributors.
- **P2** — Stale / missing / cosmetic; should be cleaned up.

---

## P0 — Security & Broken Instructions

### 1. `cookies.txt` with real session cookies is committed to git
- **Evidence**: `git ls-files cookies.txt` returns the file; it is a Netscape
  HTTP Cookie File (used for `gemini-web` cookie auth per README line ~145).
- **Impact**: Committing live auth cookies contradicts the repo's own
  "Never hardcode API keys / never leak credentials" policy in AGENTS.md.
- **Action**: Remove from version control, add to `.gitignore`, rotate the
  affected session, and document `auth cookies --file` usage with a `.gitignore`
  warning.

### 2. `deploy-worker.sh` referenced in AGENTS.md does not exist
- **Evidence**: AGENTS.md "Setup Commands" line 33 shows
  `./deploy-worker.sh --codebases /path/to/project`; `ls deploy-worker.sh` →
  missing. No matching file anywhere in repo root.
- **Impact**: A documented "one-command wrapper" fails immediately.
- **Action**: Either add the script or remove/replace the instruction with the
  actual deployment path (e.g. `docker/` or `codetether worker ...`).

## P1 — Inaccurate / Misleading Content

### 3. Inconsistent tool-count claims across docs
- **Evidence**:
  - README line 489 (Tools section): "50+ built-in tools".
  - README line 495 + 554 (MCP section): "30+ tools" / "Exposed Tools (30+)".
  - AGENTS.md line 73: "Tool implementations (27+ tools)".
  - Actual: `ls src/tool/*.rs | wc -l` → 140 files; `grep -c 'pub mod'
    src/tool/mod.rs` → 62 module declarations.
- **Impact**: Three different numbers (27+, 30+, 50+) for the same concept;
  all undercount reality.
- **Action**: Pick one authoritative count (registered tool *names*, not files)
  and reuse it everywhere, or drop hard numbers in favor of "see
  `codetether mcp list-tools`".

### 4. CHANGELOG.md is far behind the actual version
- **Evidence**: `Cargo.toml` version = `4.7.1`; latest `RELEASE_NOTES.md`
  header = `v4.7.1`. But the newest CHANGELOG entry is `## [4.0.0] - 2026-02-23`,
  and version ordering is jumbled (4.0.0, then 1.1.0, 0.1.5, 0.1.2, 0.2.0,
  0.1.0).
- **Impact**: Releases 4.1.x–4.7.1 are undocumented in the canonical changelog;
  the version ordering violates the "Keep a Changelog / SemVer" claim in its own
  header.
- **Action**: Backfill 4.x entries from RELEASE_NOTES files and reorder
  descending by version.

### 5. AGENTS.md "Project Structure" describes files that are now directories
- **Evidence** (AGENTS.md "Security Modules" + tree):
  - Claims `src/server/auth.rs` — actual: `src/server/auth/` (directory module).
  - Claims `src/tool/sandbox.rs` as *the* sandbox file — actual: `sandbox.rs`
    exists but is now one of ~50 `sandbox_*.rs` files (split for the 50-line
    rule).
  - Pitfall #9 references `auth.rs` for the `unsafe { remove_var }` pattern,
    which no longer lives at that path.
- **Impact**: Contributors following the map look in the wrong place.
- **Action**: Update paths to point at the module directories and note the
  50-line split that produced the `*_modules.rs` / `sandbox_*.rs` fan-out.

### 6. AGENTS.md omits ~30 top-level source modules
- **Evidence**: AGENTS structure block lists ~18 dirs. Actual top-level dirs
  include many undocumented ones: `actor/`, `approval/`, `autochat/`, `bus/`,
  `cognition/`, `distill/`, `event_stream/`, `forage/` (documented later but not
  in the tree), `github_pr/`, `image_clipboard/`, `indexer/`, `knowledge_graph/`,
  `marketplace/`, `memory/`, `mesh/`, `moltbook/`, `okr/`, `platform/`,
  `plugin_marketplace/`, `provenance/`, `runtime_policy/`, `search/`,
  `telemetry/`, `voice/`, `worktree_cli/`, `worktree_stub/`.
- **Action**: Regenerate the structure section from `ls -d src/*/`.

### 7. Port inconsistency between README and AGENTS.md
- **Evidence**: README uses `codetether serve --port 4096` (matches code
  default `default_value = "4096"` in `src/cli/mod.rs:266`). AGENTS.md uses
  `--server http://localhost:8001` for the worker example. The MCP/bus example
  also references `:8001`. No single doc explains which port is the server vs.
  an external A2A server.
- **Action**: Clarify that 4096 is the local `serve` default and 8001 is an
  example external A2A server URL, so they aren't read as contradictory.

## P2 — Stale / Missing / Cleanup

### 8. Stale generated rustdoc for an unrelated crate committed under `doc/`
- **Evidence**: `doc/` contains generated HTML for a crate named **`test_ts`**
  (`doc/test_ts/index.html`, `doc/src/test_ts/test_ts.rs.html`) — not
  `codetether-agent`. This is leftover `cargo doc` output from an unrelated
  project.
- **Action**: Remove `doc/` from the repo and add to `.gitignore`; generated
  docs should not be committed (and certainly not another crate's).

### 9. Developer scratch files tracked at repo root
- **Evidence**: `git ls-files` includes `.claude-prompt.md`,
  `.claude-tui-batch1.md`, `.claude-tui-batch2.md`, `codex_tui_resume_issue.md`,
  `gap-bridge.md`, `enhancements.md`.
- **Impact**: These read like transient agent/working notes, not project docs;
  they clutter the root and confuse new contributors about what is canonical.
- **Action**: Move durable content into `docs/`, delete or `.gitignore` the
  rest.

### 10. 21 `mod.rs` files lack required module-level `//!` docs
- **Evidence**: AGENTS.md "Module-Level Docs" states *every* `mod.rs` must start
  with `//!`. Files missing it include: `src/forage/mod.rs`,
  `src/github_pr/mod.rs`, `src/provenance/mod.rs`, `src/server/auth/mod.rs`,
  `src/tui/mod.rs`, `src/tui/app/mod.rs`, `src/tui/ui/mod.rs`,
  `src/cleanup_cli/mod.rs`, `src/swarm/tool_policy/mod.rs`, and 12 more.
- **Action**: Add `//!` headers; notably `forage/mod.rs` is described in detail
  in AGENTS.md yet its own source has no module doc.

### 11. 108 `TODO`/`FIXME`/`XXX` markers in `src/`
- **Evidence**: `grep -rniE 'TODO|FIXME|XXX' src --include=*.rs | wc -l` → 108.
- **Action**: Triage into tracked issues; inline TODOs are undocumented debt and
  several may flag unimplemented behavior that docs describe as complete.

### 12. `docs/` mixes living docs with one-off analysis artifacts
- **Evidence**: `docs/` holds design docs (`plugin_pattern.md`,
  `browser-capability-api.md`) alongside transient reports
  (`subtask_3_4_failure_analysis.md`, `subtask_failure_summary.md`,
  `assessment_config_main_lib.md`, `gaps-closing.json`) and even
  implementation `.rs` files (`agent-swarm-integration-examples.rs`,
  `mcp_metadata_storage_implementation.rs`). `docs/legacy/` is similarly mixed.
- **Action**: Move point-in-time analysis to `docs/legacy/` or `archive/`, keep
  `docs/` for evergreen reference, and remove `.rs` files from a docs tree.

### 13. No top-level docs index / table of contents
- **Evidence**: `docs/` has 30+ files with no `README.md` or index explaining
  what each is or which are current.
- **Action**: Add `docs/README.md` cataloguing current vs. legacy docs.
