# CodeTether Agent 4.7.6-dev.24

## Fix goal continuation after `/ask`

A goal could remain stuck after an answer was accepted if `/ask` arrived between
reserving a runtime turn and starting its executor. The answer-review gate
rejected the queued turn but left its reservation behind, so continuation was
rejected as "Session runtime is busy".

The rejection path now releases the matching unstarted reservation before
returning the session. Cleanup is atomic with steering-inbox cleanup and cannot
release a different session's reservation or an already-running executor.

The explicit answer-review decision is unchanged: Yes resumes the goal, while
No leaves it paused. Token-budget limits and tool approvals remain enforced.

## Regression coverage

- Reservation → question hold → rejected submission → accepted answer → restart.
- Cleanup of a rejected turn's steering inbox.
- Preservation of other reservations and running cancellation notifiers.
- Harmless rejection when no reservation exists.

Publication remains gated by the Forgejo verification job and Linux, Windows,
Apple Silicon, and Intel macOS builds. Local installation is not CI release proof.
