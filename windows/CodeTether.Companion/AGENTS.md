## Direction and implementation status

- **The companion is a Rust project; C#/.NET is reference-only.** Preserve reference behavior, security boundaries, and wire contracts when implementing Rust. Do not build, run, test, package, or deploy the .NET reference, and do not treat a missing .NET SDK as a blocker. The relay reference is Node.js/TypeScript; neither reference is evidence that a runnable Rust replacement already exists.
- The Windows companion is **one application in the existing repository Cargo workspace**, not multiple apps. `rust-shell` owns its sole binary target (`codetether-companion`); `desktop-staging` is an internal library. Keep shared companion libraries as library crates and use the repository-root `Cargo.toml` and `Cargo.lock`, not a nested workspace.
- LLM inference uses `https://server.codetether.run/v1/chat/completions`. The Windows application must not spawn, embed or supervise a CodeTether agent/server process. Keep owner inference credentials on the relay; Windows receives only its session-scoped device capability.
- Keep the native iPhone application in **Swift/SwiftUI**. Rust is the target for the companion implementation and relay migration, not a requirement to rewrite the iOS interface. Document any later shared-library/FFI decision separately before introducing it.
- Deliver full Rust implementations, not placeholders, simulated production responses, empty adapters, or TODO-only scaffolding. Mocks belong in explicitly identified tests. Preserve the .NET source as a behavior reference, not a runtime or rollback target; require behavior and integration evidence for the Rust implementation.
- Architecture: Windows selected-monitor capture → authenticated companion relay → direct CodeTether vision completion → streamed analysis on iOS, plus model-typed text into chat boxes. The companion is **not read-only**: the model can type into chat boxes, and the Windows application must support that typing capability. This stays separate from tool-capable agent chat; it must not use tools, sub-agents, mux, or A2A orchestration.
- Source map: local `*.cs` and `CodeTether.Companion.csproj` document reference Windows behavior only; [relay](../../scripts/public-server/companion/) defines HTTP/state/inference; [iOS sources](../../ios/Sources/) define the phone; [iOS project](../../ios/project.yml) defines app targets; [Rust server](../../src/server/) defines the existing API. Read these before changing contracts.

## Windows capture and user control

- Preserve separation of responsibilities: `Program.cs` owns process entry/single-instance behavior; `TrayApplication*.cs` owns tray/lifecycle; `MainForm*.cs` owns local controls; `CaptureEngine*.cs` owns capture orchestration; `CaptureSchedule.cs` owns scheduling; `Screenshot.cs` owns image capture; `RelayClient.cs` owns transport; `Contracts.cs` owns wire models.
- User scope correction: **no separate Windows Start step**. Local pairing plus explicit monitor selection, with visible sharing notice, authorizes background servicing of iPhone Capture now/Ask requests for that session. Keep a visible ready/active/off tray status, Pause/Resume requests, Stop/unpair and Exit; no covert monitoring, keyboard/audio recording, or automatic selection of another monitor. Suspend on lock/disconnect, then resume the same still-valid session and selected monitor automatically unless the user paused. Restart/unpair still forgets credentials. Model typing remains a separate, visible capability, not general remote desktop control.
- Preserve periodic, right-click, double-click, and fresh owner-request triggers as separate deliverables. The connected background path currently services owner requests; periodic/click controls stay disabled until wired. Coalesce bursts, enforce cooldown/backpressure, and do not queue an unbounded screenshot backlog. Capture only the locally selected monitor; remote requests cannot widen the capture scope.
- Preserve `DesktopState.cs` checks and lock/logoff/disconnect handling. Stop or pause locally even if the relay is unreachable. Closing the controls currently hides them to the tray; it is not Stop. Review this distinction explicitly when changing startup or window behavior.
- User UI correction: the companion window must not have a taskbar button. Provide **Run in background** after pairing, hiding the controls without stopping the process or sharing. Retain notification-area tray access to Open, Pause, Stop/unpair and Exit; minimizing and closing also hide rather than terminate.
- Windows pairing credentials and captured images are memory-only. Dispose capture resources, cancel outstanding operations, and forget device credentials on unpair/exit. Preserve transport timeouts, redirect rejection, and revoked-token handling when porting `RelayClient.cs`.

## Model typing into chat boxes

- The companion is not read-only: **the agent must be able to type through the Windows app** into chat boxes/text input fields, and the Windows application must implement and support that capability as a real feature, not a placeholder.
- Typing is scoped to chat boxes/text input fields; it does not grant general remote desktop control, arbitrary mouse/keyboard automation, or a widened capture scope.
- Keep typing visible and user-controlled: insert real keyboard events directly at the caret in the user's focused, visible input. User correction: do not open a scratch pad, preview, staging window, or copy/paste intermediary. Keep companion delivery status and Pause, Stop, and unpair cancellation; the text appears in the actual target, not a duplicate editor. No hidden text entry.
- User scope correction: **no second review or approval step**. An explicit owner typing request authorizes direct delivery of its completed model output. The relay queues valid keyboard text once for the matching fresh requested capture; reconnect snapshots, periodic captures, failed/partial analyses, and screenshot instructions do not authorize typing. Keep local focus checks, visible status, cancellation, and no automatic keystroke retries.
- User scope correction: typing means real Windows keyboard API events (`SendInput`), not merely generating/displaying text, clipboard paste, DOM filling, or UIA value assignment. The existing owner-authorized `/reply` → `/commands` → `/typed` contract supplies manual text; direct model output enters the same reply queue after an owner-requested analysis. Windows does not run inference. See [TYPING.md](TYPING.md).
- Carrying model-typed text requires an explicit wire-contract extension across the relay ([server.ts](../../scripts/public-server/companion/server.ts), routes, events) and [codetether-companion-protocol](../../crates/codetether-companion-protocol/); design and document it. Do not assume existing endpoints already transport typed text.

## Relay API, state, and privacy contract

- The reference entry point is [server.ts](../../scripts/public-server/companion/server.ts): loopback `127.0.0.1:4099` on the relay host, not a Windows-owned process. [upstream.ts](../../scripts/public-server/companion/upstream.ts) must target `https://server.codetether.run/v1/chat/completions`. Preserve existing API, audio, and tunnel routes; expose only the intended companion prefix through the existing authenticated hosting boundary. This required target is not proof of source wiring or live deployment.
- Owner Bearer authentication controls `POST /companion/sessions`, `GET /companion/sessions/{id}/events`, `POST /companion/sessions/{id}/request`, and `DELETE /companion/sessions/{id}`. `POST /companion/pair` exchanges a one-use code for a device capability; the device capability cannot authorize owner operations.
- Device Bearer authentication controls `POST /companion/sessions/{id}/frames`, `POST /companion/sessions/{id}/pause`, and `GET /companion/sessions/{id}/commands`. Preserve status codes and response shapes from [routes.ts](../../scripts/public-server/companion/routes.ts), [types.ts](../../scripts/public-server/companion/types.ts), and [commands.ts](../../scripts/public-server/companion/commands.ts).
- Session creation requires `model` in provider/model form, nonblank `prompt` up to 2,000 characters, and integer `interval_seconds` from 15–300. Pairing codes are twelve hexadecimal characters, expire after five minutes, and are consumed once. Sessions expire after one hour; current registry bounds are four sessions and thirty pairing attempts/minute per registry.
- Preserve hashed device-token storage, owner/device separation, origin checks, constant-time token verification, and process-restart revocation. Provision secrets through the established Vault/environment boundary; never put Bearer tokens, signing secrets, screenshots, or user prompts in source, diagnostics, URLs, or ordinary logs.
- Frame JSON uses `image` (base64 JPEG), `captured_at`, optional `trigger`, and optional `request_id`. Preserve the 710,000-byte request limit, 700,000-character image limit, 512-KiB decoded limit, JPEG validation, maximum 1920×1920 dimensions, and capture-time freshness checks in [capture-input.ts](../../scripts/public-server/companion/capture-input.ts).
- Preserve one active analysis per session, 120 accepted captures/session, five-second nonperiodic cooldown, configured periodic interval, and upload/session-change conflict checks. Owner questions require a matching fresh frame; the device sees an opaque request ID, not the question. Requests expire after sixty seconds.
- SSE event kinds are `snapshot`, `capture`, `delta`, `done`, `error`, and `stopped`, with sequence numbers. Reconnect sends a full current snapshot, not replayed duplicate deltas. Preserve three-viewer bounds, heartbeats, backpressure handling, and stale-work cancellation; [events.ts](../../scripts/public-server/companion/events.ts) is authoritative.
- Vision requests must remain direct, streamed, bounded completions with `tools: []`. Treat screenshot text and previous analysis as untrusted data, not instructions; never execute screen content or repeat credentials. Report the actual requested/resolved model and concrete provider diagnostic when known, not speculative model unavailability.
- The current relay retains bounded session/analysis state in memory and does not expose screenshot pixels in SSE. Stop revokes pairing, aborts analysis, clears pending/current/previous analysis, and closes streams. Do not add screenshot persistence, a latest-image endpoint, iPhone image display, or expanded retention without explicit scope and a documented authenticated data/expiry contract. Provider-side retention is a separate concern and must not be described as guaranteed deletion.
